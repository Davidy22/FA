# Architecture

Make Anyth.ing is a static SPA on GitHub Pages backed by a single Supabase free-tier project.

- Frontend: Next.js 14 static export (`output: 'export'`), React, Tailwind, TanStack Query, Zustand.
- Backend: Supabase Postgres + RLS + RPCs + Auth + Storage + Deno Edge Functions.
- Payments: Stripe Checkout hosted redirect + webhook. (A switch to a marketplace checkout was considered; shop.com only publishes product/affiliate APIs, so Stripe remains until a real payment provider is chosen.)
- Document printing: guests upload PDFs into random, insert-only capability paths in the private `document-prints` bucket; signed-in owners retain owner-scoped paths. `price_cart()` and `stripe-checkout` accept the same strict path shapes, and checkout always downloads the private PDF with the service role and recounts pages. The `convert-document` function proxies DOC/DOCX/ODT/Pages conversion to a private Gotenberg 8/LibreOffice service configured with `GOTENBERG_URL`.
- Staff permissions: `profiles.permissions text[]` holds module grants (`products.manage`, `coupons.manage`, `jobs.manage`, `quotes.manage`, `orders.manage`, `users.manage`, `payouts.manage`, `submissions.review`, `locations.manage`, `settings.manage`, plus `admin.full`). `public.has_permission(key)` is the single check used by RLS and SECURITY DEFINER RPCs; `admin.full` also makes `public.is_admin()` true, so existing admin policies apply unchanged. The admin console renders only the tabs the account may use.
- Product categories: `product_categories(slug, name jsonb, description, sort_order, is_active)`; `premade_products.category` and `model_submissions.category` are foreign keys (rename cascades, delete restricted, `other` protected). The catalog filter and admin forms read the table, never a bundled list.
- Filament finishes: `filament_finishes(slug, name jsonb, ...)` plus `filaments.finish` and `filaments.color_hex_2`; `web/src/lib/filaments.ts` turns a finish into a swatch (grain for wood, gradient blend for two-tone spools, glow, translucency, ...).
- Membership tiers: `profiles.lifetime_points` (earned only, never spent) plus the `rewards.tiers` setting. Member/Silver/Gold/Platinum thresholds are fixed at 0/1,000/5,000/20,000; only names and multipliers are configurable (1×/2×/3×/4× by default). `public.reward_multiplier()` mirrors `parseTiers()` in `web/src/lib/rewards.ts`; the order trigger credits `floor(total × base rate × multiplier)` and grows the lifetime total. Reward coupons expire one year after issue.
- Feature switches: `platform_settings` keys `features.model_submissions` and `features.careers_page`, read through `public.feature_enabled()` and mirrored by `useFeature()` in `web/src/lib/features.ts`. Both default to off; model submission inserts are refused by RLS while disabled.
- i18n: react-i18next standard `{{variable}}` interpolation with three locales (en, zh-Hant, zh-Hans). Key and placeholder parity is enforced by `scripts/i18n-check.mjs`; `scripts/i18n-sync.mjs` preserves translations while synchronizing future English structure changes. The initial language comes from the browser's language preference, then from its region (or time zone), then English — so a `zh-HK` browser lands on 繁體中文 while an `en-HK` browser keeps English.
- Market: Hong Kong first. Locations, orders and the demo seed default to country `HK`, currency `HKD` and `Asia/Hong_Kong`; `formatMoney` renders every amount in the location's own currency (`HK$` by default, `US$` for a location abroad). Sales tax is a property of the location's country (`public.no_sales_tax_countries()` / `sales_tax_rate()`), so Hong Kong checkout is tax-free and the tax line is omitted entirely when nothing is charged, while a taxable country keeps the rate its admin sets.
- Quotation: the `/quote` page is a contact form that opens a ticket (`tickets` / `ticket_messages` / `ticket_attachments` / `ticket_quotes`); staff reply in the thread and quote a price, which the customer accepts into the cart (`price_cart` kind `ticket`). Model verification remains available to the submission flow through `verify-model`.
- Multi-material prints: `product_material_slots` (localized name, `sort_order`, `default_material_id`, `default_filament_id`) plus `product_slot_materials` (the materials a slot may use and each one's `price_modifier`). Triggers keep a slot's default material eligible and its default colour a colour of that material. `price_cart` resolves every slot (customer pick → slot default → first eligible material), rejects picks outside the slot's list, adds the slot modifiers to the unit price, and stores the resolved slots in `item_snapshot.slots`; `create_order_from_cart` copies them to `order_items.material_slots` for the staff fulfilment screen, keeping the first slot in the legacy `material_id` / `color_filament_id` columns. A product with slots no longer needs a product-level default material to publish.
- Sale prices: `sale_price` / `sale_starts_at` / `sale_ends_at` on `premade_products` **and** `product_option_choices`. The stable helpers `sale_window_open()`, `sale_is_active()` and `effective_price()` (a null bound is open ended, the end bound is exclusive) are the single source of truth for both SQL and the storefront (`web/src/lib/sale.ts` mirrors them). Triggers require a sale price below the regular price and a window that ends after it starts. `price_cart` charges the effective price and reports `sale_savings` plus per-line `item_snapshot.regular_price` / `sale_price`, which `components/Price.tsx` renders as the regular price struck through next to the sale price.

See `supabase/migrations/` for the schema and RLS; see `supabase/functions/` for Stripe integration, model verification, and admin actions.
